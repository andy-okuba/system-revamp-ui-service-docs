## `GET /{tenantId}/{country}/transactions`

Returns a paginated list of the authenticated user's wallet transactions (deposits, withdrawals, bets, winnings, adjustments, etc.).

The endpoint accepts `lang`, `page`, `per_page`, `sort`, `transaction_type`, and `reference_id` query parameters. All supported query combinations return the same response envelope.

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. |
| `country` | `string` | Yes | Country code, e.g. `ke`. |

### Query parameters

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `lang` | `string` | `en` | Locale code. |
| `page` | `number` | `1` | 1-indexed page number. |
| `per_page` | `number` | `10` | Page size. |
| `sort` | `string` | `created\|desc` | Sort field and direction, pipe-separated. |
| `transaction_type` | `number` | `0` | `0` all, `1` credit, `2` debit. |
| `reference_id` | `number[]` | `[0]` | Filter by one or more `TransactionReferenceId` values (see reference table below). `0` = no filter. |

### Headers

| Header | Value | Required |
| --- | --- | --- |
| `Content-Type` | `application/json` | Yes |
| `api-key` | User's auth token | Yes |

### Sample request

```bash
curl -G "https://api.touchvasgaming.com/1001/ke/transactions" \
  --data-urlencode "lang=en" \
  --data-urlencode "page=1" \
  --data-urlencode "per_page=10" \
  --data-urlencode "sort=created|desc" \
  --data-urlencode "transaction_type=0" \
  -H "api-key: <user-auth-token>"
```

### Sample response

```json
{
  "current_page": 1,
  "per_page": 10,
  "total": 87,
  "last_page": 9,
  "from": 1,
  "to": 10,
  "data": [
    {
      "id": 771234,
      "created": "2026-09-22T09:15:00Z",
      "amount": 500,
      "balance": 1250.5,
      "transaction_type": "credit",
      "reference_id": "11",
      "description": 0,
      "status": 1
    }
  ]
}
```

### Response field reference

| Field | Type | Notes |
| --- | --- | --- |
| `data` | `Transaction[]` | One entry per transaction. |
| `data[].reference_id` | `string` | Maps to the `TransactionReferenceId` enum: `1` sports bet, `2` bonus bet, `3` bonus casino bet, `4` bonus winning, `5` sportsbet winning, `6` casinobet winning, `7` casino wallet adjustment, `8` casino bet, `9` withdraw, `10` jackpot bet, `11` deposit, `12` adjustment, `13` rollback, `14` freebet winning, `15` cashout. |
| `data[].transaction_type` | `string` | Human-readable label; the **query** filter of the same name is numeric (`0`/`1`/`2`) — confirm this asymmetry is intentional. |
| `data[].balance` | `number` | Running wallet balance immediately after this transaction. |
| `data[].description` | `number` | Currently typed/observed as numeric in this contract — confirm with backend whether a human-readable string was intended here. |

Each transaction may include `withdrawable_balance` for account-balance calculations.

### Tenant-scoping notes for backend

- Transaction history must only ever return records belonging to the authenticated user **within the requesting tenant**.
