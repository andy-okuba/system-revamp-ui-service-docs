## `GET /{tenantId}/{country}/sports`

Returns the list of sports available in the given country/tenant. The frontend currently filters the response down to a fixed allow-list of sport IDs client-side (`[1, 2, 5, 9, 10, 12, 21, 59, 107, 117]`) — the backend should ideally already scope this list to what the tenant actually offers, making the client-side filter redundant over time.

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. |
| `country` | `string` | Yes | Country code, e.g. `ke`. |

### Headers

| Header | Value |
| --- | --- |
| `Accept` | `application/json` |

### Sample request

```bash
curl "https://api.touchvasgaming.com/1001/ke/sports" \
  -H "Accept: application/json"
```

### Sample response

```json
[
  { "sport_id": 1, "sport_name": "Football" },
  { "sport_id": 2, "sport_name": "Basketball" },
  { "sport_id": 5, "sport_name": "Tennis" },
  { "sport_id": 9, "sport_name": "Boxing" },
  { "sport_id": 10, "sport_name": "Baseball" },
  { "sport_id": 12, "sport_name": "Handball" },
  { "sport_id": 21, "sport_name": "Cricket" },
  { "sport_id": 59, "sport_name": "Table Tennis" },
  { "sport_id": 107, "sport_name": "Esports" },
  { "sport_id": 117, "sport_name": "Futsal" }
]
```

### Response field reference

| Field | Type | Notes |
| --- | --- | --- |
| (array item) `sport_id` | `number` | Sport identifier, used in all other sport-scoped endpoints. |
| (array item) `sport_name` | `string` | Display name. |

::note
Response must be a top-level JSON **array**, not wrapped in a `data` object. The frontend treats any non-array response as an empty list.
::

### Tenant-scoping notes for backend

- Return only sports actually enabled/offered for the requesting tenant, ideally removing the need for the frontend's hard-coded sport-id allow-list.
