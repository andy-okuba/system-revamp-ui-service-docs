## `GET /{tenantId}/{country}/position/{tournamentId}`

Returns the authenticated user's own rank and points within a specific tournament, even if they don't appear on the public results page.

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. |
| `country` | `string` | Yes | Country code, e.g. `ke`. |
| `tournamentId` | `string` | Yes | The tournament `id` from [Tournaments](/api-reference/casino/tournaments). |

### Headers

| Header | Value | Required |
| --- | --- | --- |
| `api-key` | User's auth token | Yes — the frontend refuses to call this endpoint without a token and prompts the user to log in instead. |

### Sample request

```bash
curl "https://api.touchvasgaming.com/1001/ke/position/501" \
  -H "api-key: <user-auth-token>"
```

### Sample response

```json
{
  "number": "14",
  "points": "312.00"
}
```

### Response field reference

| Field | Type | Notes |
| --- | --- | --- |
| `number` | `string` | The user's rank, sent as a **string**. Displayed as `"N/A"` client-side if absent. |
| `points` | `string` | The user's tournament points, sent as a **string**. Displayed as `"N/A"` client-side if absent. |

::warning
Same string-typed `number`/`points` shape as the `position` object returned per-row by [Tournament Results](/api-reference/casino/tournament-results) — keep both endpoints consistent.
::

### Tenant-scoping notes for backend

- Must only return the position of the authenticated user **within the requesting tenant's** tournament instance; validate the user belongs to `tenantId`.
