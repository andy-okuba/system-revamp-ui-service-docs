## `PATCH /{tenantId}/{country}/profile/{userId}/password/change`

Lets an authenticated user change their password by providing their current password.

This endpoint is wrapped by the [Proof-of-Work Challenge](/api-reference/identity/proof-of-work-challenge) retry (`endpointName: "profile/password/change"`).

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. |
| `country` | `string` | Yes | Country code, e.g. `ke`. |
| `userId` | `number` | Yes | The authenticated user's own `id`. |

### Query parameters

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `lang` | `string` | `en` | Locale code. |

### Headers

| Header | Value | Required |
| --- | --- | --- |
| `Content-Type` | `application/json` | Yes |
| `api-key` | User's auth token | Yes |

### Request body

```json
{
  "old_password": "hunter2",
  "new_password": "NewHunter3"
}
```

### Sample request

```bash
curl -X PATCH "https://api.touchvasgaming.com/1001/ke/profile/55219/password/change?lang=en" \
  -H "Content-Type: application/json" \
  -H "api-key: <user-auth-token>" \
  -d '{ "old_password": "hunter2", "new_password": "NewHunter3" }'
```

### Sample response

```json
{
  "data": "Password changed successfully."
}
```

`HTTP 200` or `HTTP 201`.

### Tenant-scoping notes for backend

- Must validate `old_password` against the account **within the requesting tenant** before applying the change.
