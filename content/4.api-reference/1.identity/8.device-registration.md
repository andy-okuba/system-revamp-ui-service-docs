## `POST /{tenantId}/{country}/device`

Registers metadata about the device/browser used to log in, immediately and automatically after a successful [Login](/api-reference/identity/login), [Register](/api-reference/identity/register) or [Reset Password](/api-reference/identity/reset-password).

This endpoint is wrapped by the [Proof-of-Work Challenge](/api-reference/identity/proof-of-work-challenge) retry (`endpointName: "device"`).

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. |
| `country` | `string` | Yes | Country code, e.g. `ke`. |

### Query parameters

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `lang` | `string` | `en` | Locale code. |

### Headers

| Header | Value | Required |
| --- | --- | --- |
| `Content-Type` | `application/json` | Yes |
| `User-Agent` | The browser's user agent string, sent explicitly as a body-derived header | Yes |
| `api-key` | User's auth token, from the login/signup/verify/reset response | Yes |

### Request body

```json
{
  "fingerprint": "a1b2c3d4-fingerprint-hash",
  "ip": "41.90.64.12",
  "profile_id": 55219,
  "user_agent": "Mozilla/5.0 (...)"
}
```

| Field | Type | Notes |
| --- | --- | --- |
| `fingerprint` | `string` | Device fingerprint, from the login/signup payload if present, otherwise generated client-side. |
| `ip` | `string` | Resolved client-side via a third-party IP detection call before this request is sent. |
| `profile_id` | `number` | The `id` from the login/signup/verify response. |
| `user_agent` | `string` | `navigator.userAgent`. |

### Sample request

```bash
curl -X POST "https://api.touchvasgaming.com/1001/ke/device?lang=en" \
  -H "Content-Type: application/json" \
  -H "User-Agent: Mozilla/5.0 (...)" \
  -H "api-key: <user-auth-token>" \
  -d '{ "fingerprint": "a1b2c3d4-fingerprint-hash", "ip": "41.90.64.12", "profile_id": 55219, "user_agent": "Mozilla/5.0 (...)" }'
```

### Sample response

```json
{
  "device_id": "dev_7f6e5d4c3b2a"
}
```

`HTTP 200` or `HTTP 201`. On success, `device_id` is cached in `localStorage` client-side.

### Tenant-scoping notes for backend

- `profile_id` must be validated as belonging to the requesting tenant before the device record is created.
