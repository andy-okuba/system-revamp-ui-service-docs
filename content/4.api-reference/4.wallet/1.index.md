## Purpose

This section defines the **multi-tenant contract** for every **Wallet** endpoint.

::note
The payload shapes below are the contract for balances, deposits, withdrawals, and transaction history.
::

## Base URLs

Three distinct backend hosts are involved, unified here under one neutral gateway domain:

```
https://api.touchvasgaming.com   (Wallet host — NUXT_PUBLIC_BASE_WALLET_URL)
https://api.touchvasgaming.com   (Bonus host — NUXT_PUBLIC_BASE_BONUS_URL)
https://api.touchvasgaming.com   (Payment Gateway host — NUXT_PUBLIC_PAYMENT_GW_URL)
```

All endpoints use `/{tenantId}/{country}/` as the first two path segments.

```text
GET https://api.touchvasgaming.com/1001/ke/balance?lang=en
```

## Endpoint index

| # | Method | Path | Purpose |
| --- | --- | --- | --- |
| 1 | `GET` | `/{tenantId}/{country}/balance` | Main + bonus wallet balance |
| 2 | `GET` | `/{tenantId}/{country}/bonus/balance` | Detailed bonus balance and active/pending bonuses |
| 3 | `GET` | `/{tenantId}/{country}/transactions` | Paginated transaction history |
| 4 | `GET` | `/{tenantId}/{country}/get/settings` | Deposit/withdrawal limits |
| 5 | `POST` | `/{tenantId}/{country}/deposit` **or** `/{tenantId}/{country}/deposit/initiate` | Initiate a deposit — **two competing implementations, see below** |
| 6 | `POST` | `/{tenantId}/{country}/deposit/status` | Check deposit status |
| 7 | `POST` | `/{tenantId}/{country}/withdraw` | Withdraw funds to a payment channel |
| 8 | `GET` / `POST` | `/{tenantId}/{country}/profile/channels` | List / add a payment channel (account) |
| 9 | `GET` | `/{tenantId}/{country}/profile/channels/resend/{id}` | Resend the OTP for a pending channel verification |
| 10 | `POST` | `/{tenantId}/{country}/profile/channels/verify/{id}` | Verify a payment channel with an OTP |
| 11 | `DELETE` | `/{tenantId}/{country}/profile/channels/{id}` | Remove a payment channel |
| 12 | `POST` | `/{tenantId}/{country}/campaign/redeem` | Redeem a bonus campaign code |

Each endpoint is documented with path/query parameters, headers, sample requests, and precise request/response contracts.

## Common conventions across all endpoints

- **`lang`**: locale code, e.g. `en`. Sent as a query parameter where the frontend currently uses it (see per-endpoint warnings where it is missing today).
- **`{country}`**: lowercase ISO-like country code, e.g. `ke`, immediately after `{tenantId}`.
- **Authentication**: Every endpoint in this category requires an `api-key` header carrying the user's session/auth token — the wallet is always tied to an authenticated user. A `401` response is treated uniformly by the frontend as `"Unauthorized - session expired"`.
- **Content type**: All requests/responses are `application/json`.
- **Errors**: The frontend reads `error_message` from the JSON error body (`fetchError.data?.error_message`), falling back to a generic per-action message. Standardize on `error_message`; see the [recommended error envelope](/api-reference/fixture-sports#recommended-error-envelope).

### Tenant-scoping notes for backend (apply to all endpoints in this category)

- Balances, bonuses, deposit/withdrawal limits, payment channels and transaction history are all scoped to **the authenticated user within the requesting tenant** — validate the user belongs to `tenantId` and reject cross-tenant requests with `403 Forbidden`.
- Money-moving endpoints (`deposit`, `withdraw`, `campaign/redeem`, channel create/verify/delete) are hard-to-reverse operations — ensure idempotency and tenant-aware audit logging.
