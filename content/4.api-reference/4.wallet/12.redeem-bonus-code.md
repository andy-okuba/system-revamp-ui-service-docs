## `POST /{tenantId}/{country}/campaign/redeem`

Redeems a promotional bonus code, crediting the user's bonus balance on success.

Consumed by `redeemCampaignBonusCode` in `stores/walletStore.js`. Note this call is made to the **Bonus** host, not the Wallet host.

::warning
This is the **only** endpoint in the Wallet category currently called with **no `lang` and no `country_code` at all** — under the new standard it still requires the mandatory `/{tenantId}/{country}/` path prefix even though no query parameters are sent today.
::

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. |
| `country` | `string` | Yes | Country code, e.g. `ke`. |

### Headers

| Header | Value | Required |
| --- | --- | --- |
| `Content-Type` | `application/json` | Yes |
| `api-key` | User's auth token | Yes |

### Request body

```json
{
  "bonus_code": "WELCOME100",
  "device_id": 1234567,
  "ip": "41.90.64.12"
}
```

| Field | Type | Notes |
| --- | --- | --- |
| `bonus_code` | `string` | The promotional code entered by the user. |
| `device_id` | `number` | Device identifier for fraud/abuse detection. |
| `ip` | `string` | Client IP address. |

### Sample request

```bash
curl -X POST "https://api.touchvasgaming.com/1001/ke/campaign/redeem" \
  -H "Content-Type: application/json" \
  -H "api-key: <user-auth-token>" \
  -d '{ "bonus_code": "WELCOME100", "device_id": 1234567, "ip": "41.90.64.12" }'
```

### Sample response — success

```json
{
  "data": "Bonus code redeemed successfully",
  "status": 201
}
```

### Sample response — failure

```json
{
  "error_code": 422,
  "error_message": "This bonus code has already been used."
}
```

Success is `HTTP 201`; on success the frontend re-fetches [Bonus Balance](/api-reference/wallet/bonus-balance).

### Tenant-scoping notes for backend

- Bonus campaign codes must be scoped to (and only redeemable within) the tenant that issued them.
