## `GET /{tenantId}/{country}/bonus/balance`

Returns detailed bonus information beyond the single `b2` figure from [Balance](/api-reference/wallet/balance): freebet balance, active bonus items with their own rollover requirements, and pending bonuses/deposits awaiting activation.

Consumed by `fetchBonusBalance` in `stores/walletStore.js`. Note this call is made to the **Bonus** host, not the Wallet host.

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. |
| `country` | `string` | Yes | Country code, e.g. `ke`. |

### Query parameters

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `lang` | `string` | `en` | Locale code. |

### Headers

| Header | Value | Required |
| --- | --- | --- |
| `Content-Type` | `application/json` | Yes |
| `api-key` | User's auth token | Yes |

### Sample request

```bash
curl -G "https://api.touchvasgaming.com/1001/ke/bonus/balance" \
  --data-urlencode "lang=en" \
  -H "api-key: <user-auth-token>"
```

### Response field reference

| Field | Type | Notes |
| --- | --- | --- |
| `freebet_balance` | `number` | If omitted, the frontend derives it by summing `bonus[].balance` for entries with `is_freebet: true` — prefer always sending it explicitly. |
| `has_freebet` | `boolean` | If omitted, derived client-side as `freebet_balance > 0`. |
| `bonus` | `BonusItem[]` | Active bonuses, each with its own `requirements` used to validate whether a bet slip qualifies. |
| `pending_bonus` | `PendingBonus[]` | Bonuses awaiting activation (e.g. first-deposit-triggered bonuses before the deposit lands). |
| `rollover` | `number` | Wagering requirement multiplier remaining. |

### Tenant-scoping notes for backend

- Bonus campaigns, rollover rules and requirements are tenant-specific promotional configuration.
