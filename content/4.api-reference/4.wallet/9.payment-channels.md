## `GET` / `POST /{tenantId}/{country}/profile/channels`

**`GET`** lists the payment channels (banks/mobile money providers) and any accounts the user has already linked. **`POST`** adds/links a new account to a channel, which then requires OTP verification (see [Channel Verification](/api-reference/wallet/channel-verification)).

Consumed by `fetchChannels` and `createPaymentChannel` in `stores/walletStore.js`.

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. |
| `country` | `string` | Yes | Country code, e.g. `ke`. |

### Query parameters

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `lang` | `string` | `en` | Locale code. |

### Headers

| Header | Value | Required |
| --- | --- | --- |
| `Content-Type` | `application/json` | Yes |
| `api-key` | User's auth token | Yes |

### `POST` request body

```json
{
  "account_number": "2547XXXXXXXX",
  "account_type": 1,
  "country_code": "ke",
  "payment_channel_id": 3,
  "profile_id": 55219
}
```

`POST` success is `HTTP 201`; the frontend then re-fetches the channel list.

### Sample `GET` request

```bash
curl -G "https://api.touchvasgaming.com/1001/ke/profile/channels" \
  --data-urlencode "lang=en" \
  -H "api-key: <user-auth-token>"
```

### Sample response

```json
[
  {
    "id": 3,
    "name": "M-Pesa",
    "logo": "https://cdn.example.com/channels/mpesa.png",
    "provider_type": "mobile_money",
    "accounts": [
      { "id": 9001, "account_number": "2547XXXXXXXX", "account_type": 1, "verified": 1 }
    ],
    "banks": []
  }
]
```

### Response field reference

| Field | Type | Notes |
| --- | --- | --- |
| (array item) `id` | `number` | Used as `payment_channel_id` on [Deposit](/api-reference/wallet/deposit) and [Withdraw](/api-reference/wallet/withdraw). |
| (array item) `accounts` | `PaymentAccount[]` | Accounts the user has already linked to this channel. |
| (array item) `accounts[].verified` | `0 \| 1` | Only verified (`1`) accounts should be usable for withdrawal. |
| (array item) `banks` | `Bank[]` | Present for bank-transfer-style channels; each bank has its own nested `account[]`. |

::note
Must be a top-level JSON **array** — the frontend assigns the raw parsed body directly with no `data`-wrapper fallback for this endpoint.
::

### Tenant-scoping notes for backend

- Available channels are tenant-specific (payment provider integrations differ per operator); linked accounts must be scoped to the authenticated user within the tenant.
