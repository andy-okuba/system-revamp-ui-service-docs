## `DELETE /{tenantId}/{country}/profile/channels/{id}`

Removes a previously linked payment channel account.

Consumed by `deleteChannel` in `stores/walletStore.js`.

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. |
| `country` | `string` | Yes | Country code, e.g. `ke`. |
| `id` | `number` | Yes | The payment account `id` to remove. |

### Query parameters

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `lang` | `string` | `en` | Locale code. |

### Headers

| Header | Value | Required |
| --- | --- | --- |
| `Content-Type` | `application/json` | Yes |
| `api-key` | User's auth token | Yes |

### Sample request

```bash
curl -X DELETE "https://api.touchvasgaming.com/1001/ke/profile/channels/9001?lang=en" \
  -H "Content-Type: application/json" \
  -H "api-key: <user-auth-token>"
```

### Sample response

```json
{
  "data": "Channel removed successfully"
}
```

::warning
Success is recognized by the frontend **only** via `HTTP 201` (not the conventional `200` or `204` typically used for `DELETE`) — confirm this is intentional, as it's an unusual status code choice for a delete operation.
::

On success, the frontend removes the channel from its local list by `id` without re-fetching.

### Tenant-scoping notes for backend

- Must only allow deletion of accounts owned by the authenticated user within the requesting tenant.
