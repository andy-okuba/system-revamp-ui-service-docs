## `POST /{tenantId}/{country}/profile/subscriber/credentials`

Registers a Firebase Cloud Messaging (FCM) device token against the authenticated user's profile, so push notifications can be delivered via the notification provider.

Consumed by `registerDeviceToken` in `composables/usePushNotifications.ts`.

::warning
This is the **only** endpoint from the original brief's Identity section, and it currently has a real bug worth fixing alongside the multi-tenant migration: the frontend calls a **hardcoded** production URL (`https://identity.<original-brand-domain>/profile/subscriber/credentials?lang=en`) instead of the `NUXT_PUBLIC_BASE_IDENTITY_URL` runtime variable it reads into an otherwise-unused local (`identityBaseUrl`). It must be updated to use the configured base URL **and** the mandatory `/{tenantId}/{country}/` prefix — today it has neither multi-tenant nor multi-environment support.
::

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. |
| `country` | `string` | Yes | Country code, e.g. `ke`. |

### Query parameters

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `lang` | `string` | `en` | Locale code. |

### Headers

| Header | Value | Required |
| --- | --- | --- |
| `Content-Type` | `application/json` | Yes |
| `Accept` | `application/json` | Yes |
| `api-key` | User's auth token | Yes |

### Request body

```json
{
  "channel": "web",
  "credentials": "fcm-device-token-string"
}
```

| Field | Type | Notes |
| --- | --- | --- |
| `channel` | `string` | Always `"web"` today — this endpoint is only called from the browser client. |
| `credentials` | `string` | The FCM registration token obtained from Firebase Messaging. |

### Sample request

```bash
curl -X POST "https://api.touchvasgaming.com/1001/ke/profile/subscriber/credentials?lang=en" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -H "api-key: <user-auth-token>" \
  -d '{ "channel": "web", "credentials": "fcm-device-token-string" }'
```

### Sample response

The frontend does not read any fields from the response body — it only checks `response.ok`. Confirm the intended success/error contract with backend; recommend at minimum:

```json
{
  "success": true
}
```

### Tenant-scoping notes for backend

- The device token must be associated with the user **within the requesting tenant**, so notifications are dispatched via that tenant's own notification provider configuration.
