## `POST /{tenantId}/{country}/verify`

Verifies the OTP sent after [Login](/api-reference/identity/login) or [Register](/api-reference/identity/register), establishing the user's session on success.

Consumed by `verifyOTP` in `stores/authStore.js`. Wrapped by the [Proof-of-Work Challenge](/api-reference/identity/proof-of-work-challenge) retry (`endpointName: "verify"`).

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. |
| `country` | `string` | Yes | Country code, e.g. `ke`. |

### Query parameters

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `lang` | `string` | `en` | Locale code. |

### Headers

| Header | Value |
| --- | --- |
| `Content-Type` | `application/json` |

### Request body

```json
{
  "country_code": "ke",
  "msisdn": 254712345678,
  "code": 4821,
  "finger_print": "a1b2c3d4-fingerprint-hash",
  "login_tag": 1
}
```

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `country_code` | `string` | Yes | — |
| `msisdn` | `number` | Yes | — |
| `code` | `number` | Yes | The 4-digit OTP, sent as a **number**. |
| `finger_print` | `string` | No | — |
| `email`, `username` | `string` | No | Alternate identifiers, present in the shared type but not currently populated by this flow. |
| `login_tag` | `number` | No | Distinguishes post-login vs. post-signup verification context, if the backend needs it. |

### Sample request

```bash
curl -X POST "https://api.touchvasgaming.com/1001/ke/verify?lang=en" \
  -H "Content-Type: application/json" \
  -d '{ "country_code": "ke", "msisdn": 254712345678, "code": 4821 }'
```

### Sample response

Same `Identity` shape as [Login](/api-reference/identity/login):

```json
{
  "id": 55219,
  "msisdn": "254712345678",
  "first_name": "Jane",
  "last_name": "Kamau",
  "referral_code": "JANE55219",
  "status": 1,
  "auth": "eyJhbGciOiJIUzI1NiIs..."
}
```

`HTTP 200` or `HTTP 201` establish the session.

### Tenant-scoping notes for backend

- OTP codes must be scoped to the `msisdn` **within the requesting tenant** — do not allow a code issued for one tenant's account to verify against another.
