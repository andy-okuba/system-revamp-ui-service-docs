## `POST /{tenantId}/{country}/login`

Authenticates a user with their phone number (`msisdn`) and password. May require OTP verification depending on account/risk state.

This endpoint is wrapped by the [Proof-of-Work Challenge](/api-reference/identity/proof-of-work-challenge) retry (`endpointName: "login"`).

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. |
| `country` | `string` | Yes | Country code, e.g. `ke`. |

### Query parameters

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `lang` | `string` | `en` | Locale code. |

### Headers

| Header | Value |
| --- | --- |
| `Content-Type` | `application/json` |

### Request body

```json
{
  "msisdn": 254712345678,
  "password": "hunter2",
  "finger_print": "a1b2c3d4-fingerprint-hash",
  "country_code": "ke",
  "source": "1",
  "medium": "null",
  "campaign": "null",
  "utm_source": "null"
}
```

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `msisdn` | `number` | Yes | Phone number, sent as a **number** (no leading `+` or `0`). |
| `password` | `string` | Yes | — |
| `finger_print` | `string` | No | Visitor fingerprint; auto-generated client-side if omitted. |
| `country_code`, `source`, `medium`, `campaign`, `referrer`, `browser`, `channel`, `channel_id`, `device_info`, `engine`, `fbclid`, `gclid`, `username`, `utm_*`, `btag`, `click_id`, `version_info`, `code` | various | No | Attribution/device metadata; also reused as the shared shape for [Register](/api-reference/identity/register). |

### Sample request

```bash
curl -X POST "https://api.touchvasgaming.com/1001/ke/login?lang=en" \
  -H "Content-Type: application/json" \
  -d '{ "msisdn": 254712345678, "password": "hunter2" }'
```

### Sample response — logged in directly

```json
{
  "id": 55219,
  "msisdn": "254712345678",
  "first_name": "Jane",
  "last_name": "Kamau",
  "referral_code": "JANE55219",
  "status": 1,
  "auth": "eyJhbGciOiJIUzI1NiIs...",
  "country_code": "ke"
}
```

`HTTP 200` = logged in immediately; the frontend then automatically calls [Device Registration](/api-reference/identity/device-registration).
`HTTP 202` = also treated as an immediate successful login (same response shape).

### Sample response — OTP required

`HTTP 201` or `HTTP 204` (empty or minimal body) signal that an OTP has been sent and the frontend must prompt for it via [Verify OTP](/api-reference/identity/verify-otp); no session is established yet.

### Response field reference

| Field | Type | Notes |
| --- | --- | --- |
| `auth` | `string` | Session/auth token, sent as the `api-key` header value on all subsequent authenticated requests. |
| `status` | `number` | Account status flag; interpreted by other flows (e.g. self-exclusion checks). |

### Tenant-scoping notes for backend

- `msisdn` uniqueness must be scoped **per tenant** — the same phone number may hold separate accounts under different tenants.
- The returned `auth` token must be validated against `tenantId` on every subsequent request across all categories.
