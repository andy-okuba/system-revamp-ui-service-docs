## Purpose

This section documents every **Identity** endpoint currently consumed by the sportsbook Nuxt UI service, and defines the **multi-tenant contract** the backend team must implement going forward.

The client code for these endpoints lives in:

- `stores/authStore.js`, `composables/useAuth.js` — bundled from the internal `identity-ui-service` package (login, registration, OTP, password reset, device registration, self-exclusion, username/password management)
- `utils/powChallenge.js` (same package) — the anti-bot **Proof-of-Work challenge** mechanism wrapping every Identity write endpoint
- `composables/usePushNotifications.ts` — a separate, direct call to register a push-notification device token

::note
This documentation exists so the backend team can implement the multi-tenant payload contract **exactly** as consumed by the frontend. Any deviation from the shapes below will break login, registration or account security flows without additional frontend changes.
::

## Important correction to the original endpoint categorization

::warning
The original brief listed only a single Identity endpoint (`POST /profile/subscriber/credentials`). Code review of the bundled `identity-ui-service` package shows the Identity host is actually the backbone of the **entire authentication system** — login, signup, OTP verification, password reset, device registration, self-exclusion, username setup and password change all live here. These are documented in full below.
::

## Current (single-tenant) base URL

```
https://api.touchvasgaming.com
```

Configured via the `NUXT_PUBLIC_BASE_IDENTITY_URL` runtime environment variable on the frontend.

## Required change: tenant scoping

Same platform-wide rule as the rest of the API (see the [Fixture / Sports overview](/api-reference/fixture-sports) for the full contract): every endpoint **must** accept `/{tenantId}/{country}/` as the **first two path segments** — mandatory, no exceptions.

```diff
- POST https://api.touchvasgaming.com/login?lang=en&country_code=ke
+ POST https://api.touchvasgaming.com/1001/ke/login?lang=en
```

::warning
`composables/usePushNotifications.ts` calls a **hardcoded** production URL (not the `NUXT_PUBLIC_BASE_IDENTITY_URL` runtime variable it otherwise reads into an unused local, and not tenant/country-aware at all) — this is a pre-existing configuration bug, flagged separately from the multi-tenant migration itself, and must be fixed regardless.
::

## Endpoint index

| # | Method | Path (multi-tenant) | Purpose |
| --- | --- | --- | --- |
| 1 | `POST` | `/{tenantId}/{country}/login` | Authenticate with phone number + password |
| 2 | `POST` | `/{tenantId}/{country}/signup` | Register a new account |
| 3 | `POST` | `/{tenantId}/{country}/verify` | Verify an OTP (post-login or post-signup) |
| 4 | `PATCH` | `/{tenantId}/{country}/password/forgot` | Request a password-reset OTP |
| 5 | `PATCH` | `/{tenantId}/{country}/password/reset` | Reset password using an OTP |
| 6 | `POST` | `/{tenantId}/{country}/device` | Register the current device/session fingerprint |
| 7 | `PATCH` | `/{tenantId}/{country}/profile/exclude` | Self-exclude the account for a period |
| 8 | `PATCH` | `/{tenantId}/{country}/profile/{userId}/username/setup` | Set up a username + confirm password |
| 9 | `PATCH` | `/{tenantId}/{country}/profile/{userId}/password/change` | Change the account password |
| 10 | `POST` | `/{tenantId}/{country}/profile/subscriber/credentials` | Register a push-notification device token |
| — | `POST` | `/{tenantId}/{country}/challenge` | Anti-bot Proof-of-Work challenge, see [Proof-of-Work Challenge](/api-reference/identity/proof-of-work-challenge) |

Each endpoint is documented in its own page with path/query parameters, headers, sample requests and precise sample responses matching the frontend TypeScript contracts.

## Common conventions across all endpoints

- **`lang`**: locale code, e.g. `en`. Sent as a query parameter on every endpoint.
- **`{country}`**: lowercase ISO-like country code, e.g. `ke`. Now a **mandatory path segment**, immediately after `{tenantId}` — replaces the old `country_code` query parameter.
- **Proof-of-Work retry**: Endpoints 1–9 are wrapped in a client-side retry helper that reacts to `HTTP 428 Precondition Required` by solving an anti-bot challenge and retrying once with `X-PoW-Id`/`X-PoW-Nonce` headers. See [Proof-of-Work Challenge](/api-reference/identity/proof-of-work-challenge) — backend teams implementing rate-limiting/bot-protection on these endpoints must support this handshake.
- **Authentication**: `device`, `profile/exclude`, `profile/{userId}/username/setup` and `profile/{userId}/password/change` require an `api-key` header. `login`, `signup`, `verify`, `password/forgot` and `password/reset` do not (they establish or recover the session itself).
- **Content type**: All requests/responses are `application/json`.
- **Errors**: The frontend reads `error_message` from the JSON error body. Standardize on this; see the [recommended error envelope](/api-reference/fixture-sports#recommended-error-envelope).

### Tenant-scoping notes for backend (apply to all endpoints in this category)

- Accounts are tenant-scoped: the same `msisdn` may legitimately register separate accounts under different tenants — `login`/`signup`/`verify` must resolve/create the account **within** the requesting `tenantId`, never across tenants.
- `api-key` (the `auth` token returned by login/signup/verify) must itself be tenant-bound; validate it against `tenantId` on every authenticated call across **all** categories, not just Identity.
- Proof-of-Work difficulty/expiry may reasonably vary per tenant (e.g. stricter bot protection for higher-risk markets).
