## `POST /{tenantId}/{country}/signup`

Registers a new account. Almost always requires OTP verification before a session is established.

Consumed by `register` in `stores/authStore.js`. Wrapped by the [Proof-of-Work Challenge](/api-reference/identity/proof-of-work-challenge) retry (`endpointName: "signup"`).

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. |
| `country` | `string` | Yes | Country code, e.g. `ke`. |

### Query parameters

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `lang` | `string` | `en` | Locale code. |

### Headers

| Header | Value |
| --- | --- |
| `Content-Type` | `application/json` |

### Request body

Extends the [Login](/api-reference/identity/login) request body with:

```json
{
  "msisdn": 254712345678,
  "password": "hunter2",
  "country_code": "ke",
  "first_name": "Jane",
  "last_name": "Kamau",
  "address": "Nairobi",
  "nationality": "KE",
  "id_number": "12345678",
  "date_of_birth": "1995-04-12",
  "referral_code": "FRIEND100"
}
```

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `first_name`, `last_name` | `string` | No | — |
| `address`, `nationality`, `id_number`, `date_of_birth` | `string` | No | KYC fields; confirm with backend/compliance which are actually mandatory per jurisdiction. |
| `referral_code` | `string` | No | Referrer's code, if the user signed up via a referral link. |

Plus all attribution/device metadata fields shared with [Login](/api-reference/identity/login).

### Sample request

```bash
curl -X POST "https://api.touchvasgaming.com/1001/ke/signup?lang=en" \
  -H "Content-Type: application/json" \
  -d '{
    "msisdn": 254712345678,
    "password": "hunter2",
    "country_code": "ke",
    "first_name": "Jane",
    "last_name": "Kamau"
  }'
```

### Sample response — OTP required (typical)

```json
{
  "data": "An OTP has been sent to your phone number."
}
```

`HTTP 201` — the frontend surfaces `data` as a message and prompts for [Verify OTP](/api-reference/identity/verify-otp); no session is established yet.

### Sample response — registered directly

`HTTP 202` returns the same `Identity` shape documented in [Login](/api-reference/identity/login) and establishes a session immediately (no OTP required) — the frontend then calls [Device Registration](/api-reference/identity/device-registration).

### Tenant-scoping notes for backend

- New accounts must be created **within** the requesting tenant; `referral_code` lookups must also be scoped to the same tenant.
