## `PATCH /{tenantId}/{country}/password/forgot`

Requests a password-reset OTP to be sent to the account's phone number.

This endpoint is wrapped by the [Proof-of-Work Challenge](/api-reference/identity/proof-of-work-challenge) retry (`endpointName: "password/forgot"`).

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. |
| `country` | `string` | Yes | Country code, e.g. `ke`. |

### Query parameters

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `lang` | `string` | `en` | Locale code. |

### Headers

| Header | Value |
| --- | --- |
| `Content-Type` | `application/json` |

### Request body

```json
{
  "country_code": "ke",
  "msisdn": 254712345678
}
```

### Sample request

```bash
curl -X PATCH "https://api.touchvasgaming.com/1001/ke/password/forgot?lang=en" \
  -H "Content-Type: application/json" \
  -d '{ "country_code": "ke", "msisdn": 254712345678 }'
```

### Sample response

```json
{
  "data": "A password reset code has been sent to your phone number."
}
```

::note
The frontend treats **any** non-throwing response as success and displays `data` as a message — it does not branch on a specific HTTP status here. Confirm with backend whether a distinct error status/body is returned for unknown `msisdn`, and ensure it still resolves to a rejected promise (thrown error) rather than a 2xx with an error message inside `data`.
::

### Tenant-scoping notes for backend

- Must only resolve accounts **within the requesting tenant** for the given `msisdn`.
