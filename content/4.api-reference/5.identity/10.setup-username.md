## `PATCH /{tenantId}/{country}/profile/{userId}/username/setup`

Lets an authenticated user set (or change) their username, re-confirming their current password.

This endpoint is wrapped by the [Proof-of-Work Challenge](/api-reference/identity/proof-of-work-challenge) retry (`endpointName: "profile/username/setup"`).

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. |
| `country` | `string` | Yes | Country code, e.g. `ke`. |
| `userId` | `number` | Yes | The authenticated user's own `id` — the frontend never calls this for another user. |

### Query parameters

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `lang` | `string` | `en` | Locale code. |

### Headers

| Header | Value | Required |
| --- | --- | --- |
| `Content-Type` | `application/json` | Yes |
| `api-key` | User's auth token | Yes |

### Request body

```json
{
  "username": "jane_k",
  "password": "hunter2"
}
```

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `username` | `string` | Yes | Desired username. |
| `password` | `string` | Yes | Current password, re-confirmed for this sensitive change. |

### Sample request

```bash
curl -X PATCH "https://api.touchvasgaming.com/1001/ke/profile/55219/username/setup?lang=en" \
  -H "Content-Type: application/json" \
  -H "api-key: <user-auth-token>" \
  -d '{ "username": "jane_k", "password": "hunter2" }'
```

### Sample response

```json
{
  "data": "Username updated successfully."
}
```

Success is `HTTP 201` only.

### Tenant-scoping notes for backend

- Username uniqueness should be scoped **per tenant** (consistent with `msisdn` scoping on [Login](/api-reference/identity/login)), unless product requires globally unique usernames — confirm with backend/product.
