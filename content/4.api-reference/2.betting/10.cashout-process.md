## `POST /{tenantId}/{country}/cashout/request/process`

Confirms and executes the cashout previously quoted via [Cashout Request](/api-reference/betting/cashout-request). On success, the frontend refreshes the user's bet history.

Consumed by `processCashout` in `betHistoryStore.js`.

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. |
| `country` | `string` | Yes | Country code, e.g. `ke`. |

### Query parameters

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `lang` | `string` | `en` | Locale code. |

### Headers

| Header | Value | Required |
| --- | --- | --- |
| `Content-Type` | `application/json` | Yes |
| `api-key` | User's auth token | Yes |

### Request body

```json
{
  "bet_id": 9081726
}
```

Same shape as [Cashout Request](/api-reference/betting/cashout-request).

### Sample request

```bash
curl -X POST "https://api.touchvasgaming.com/1001/ke/cashout/request/process?lang=en" \
  -H "Content-Type: application/json" \
  -H "api-key: <user-auth-token>" \
  -d '{ "bet_id": 9081726 }'
```

### Sample response

```json
{
  "amount": 95.5,
  "description": "Cashout processed successfully",
  "status": 1
}
```

Same response shape as [Cashout Request](/api-reference/betting/cashout-request) (`amount`, `description`, `status`). A `status`/`amount` of `0`, or a non-2xx HTTP status, is treated as a failed cashout attempt.

### Tenant-scoping notes for backend

- Re-validate cashout eligibility server-side at process time (odds/availability may have changed since the quote) — do not trust the quoted amount from the request step without re-pricing.
- This is a money-moving, hard-to-reverse operation — ensure idempotency (e.g. reject a second process call for an already-cashed-out `bet_id`).
