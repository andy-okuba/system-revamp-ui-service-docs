## Purpose

This section documents every **Betting** endpoint currently consumed by the sportsbook Nuxt UI service, and defines the **multi-tenant contract** the backend team must implement going forward.

The client code for these endpoints lives in:

- `stores/bettingStore.js`, `stores/betHistoryStore.js` — bundled from the internal `betting-ui-service` package (bet placement, settings, WinBoost, freebet, leaderboard, bet history, cashout)
- `composables/useBoostedBets.ts`, `composables/useWinBoost.ts` — thin wrappers used directly by the sportsbook UI

::note
This documentation exists so the backend team can implement the multi-tenant payload contract **exactly** as consumed by the frontend. Any deviation from the shapes below will break bet placement, bet history, or cashout without additional frontend changes.
::

## Current (single-tenant) base URL

```
https://api.touchvasgaming.com
```

Configured via the `NUXT_PUBLIC_BASE_BETTING_URL` runtime environment variable on the frontend.

## Required change: tenant scoping

Same platform-wide rule as the rest of the API (see the [Fixture / Sports overview](/api-reference/fixture-sports) for the full contract): every endpoint **must** accept a numeric `tenantId` followed by `{country}` as the **first two path segments** — `/{tenantId}/{country}/<existing-path>`. This is mandatory with no exceptions, even though Betting endpoints did not previously have a `{country}` path segment.

```diff
- GET https://api.touchvasgaming.com/bet/boost
+ GET https://api.touchvasgaming.com/1001/ke/bet/boost
```

::warning
Betting endpoints previously accepted country only as a `country_code` **query parameter**. Under the new standard, `{country}` moves into the path (`/{tenantId}/{country}/...`) and the `country_code` query parameter is dropped — it becomes redundant and must not be required going forward. `lang` remains a query parameter, unchanged. **The response payload for every endpoint below is unchanged from the current implementation** — only the request path changes.
::

## Endpoint index

| # | Method | Path (multi-tenant) | Purpose |
| --- | --- | --- | --- |
| 1 | `GET` | `/{tenantId}/{country}/get/settings` | Stake limits, odds limits and tax settings used to validate bets client-side |
| 2 | `GET` | `/{tenantId}/{country}/winboost` | WinBoost tiered payout-boost configuration |
| 3 | `POST` | `/{tenantId}/{country}/bet` | Place a bet (single, multibet, bonus or freebet) |
| 4 | `GET` | `/{tenantId}/{country}/bet` | Paginated bet history for the authenticated user |
| 5 | `GET` | `/{tenantId}/{country}/bet/boost` | Curated list of boosted-odds bet slips shown in the carousel |
| 6 | `GET` | `/{tenantId}/{country}/bookings/{bookingCode}` | Resolve a shared booking code into its selections |
| 7 | `GET` | `/{tenantId}/{country}/freebet/fixture` | The fixture currently eligible for a promotional freebet |
| 8 | `POST` | `/{tenantId}/{country}/cashout/request` | Quote the current cashout value/availability for a bet |
| 9 | `POST` | `/{tenantId}/{country}/cashout/request/process` | Confirm and execute a cashout |
| 10 | `GET` | `/{tenantId}/{country}/leaderboard` | Weekly sportsbook leaderboard and the caller's own rank |

Each endpoint is documented in its own page with path/query parameters, headers, sample requests and precise sample responses matching the frontend TypeScript contracts.

## Common conventions across all endpoints

- **`lang`**: locale code, e.g. `en`. Sent as a query parameter on most endpoints.
- **`{country}`**: lowercase ISO-like country code, e.g. `ke`. Now a **mandatory path segment**, immediately after `{tenantId}` — replaces the old `country_code` query parameter.
- **Authentication**: Endpoints that act on a specific user (`bet` place/history, `cashout/*`, `leaderboard`) require an `api-key` header carrying the user's session/auth token. Endpoints that return static/shared configuration (`get/settings`, `winboost`, `bet/boost`, `freebet/fixture`, `bookings/{bookingCode}`) are called without `api-key` today.
- **Content type**: All responses are `application/json`.
- **Errors**: The frontend reads `error_message` (preferred) or `message` from the JSON error body. Standardize on `error_message` going forward; see the [recommended error envelope](/api-reference/fixture-sports#recommended-error-envelope) used platform-wide.

### Tenant-scoping notes for backend (apply to all endpoints in this category)

- Stake limits, odds limits, WinBoost tiers, boosted bet slips, freebet promotions and the leaderboard must all reflect the requesting **tenant's** own configuration/campaigns — none of this data is shared across tenants.
- `api-key` identifies the user; validate that the authenticated user belongs to the given `tenantId` and reject cross-tenant requests with `403 Forbidden`.
- Bet history, cashout and booking-code lookups must be scoped so a user/booking code from one tenant can never be read or acted upon through another tenant's `tenantId`.
