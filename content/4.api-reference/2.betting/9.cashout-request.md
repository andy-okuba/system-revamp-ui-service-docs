## `POST /{tenantId}/{country}/cashout/request`

Requests a real-time cashout quote for a specific bet. This does **not** execute the cashout — it only returns the amount currently offered, which the user must then confirm via [Cashout Process](/api-reference/betting/cashout-process).

Consumed by `requestForCashout` in `betHistoryStore.js`.

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. |
| `country` | `string` | Yes | Country code, e.g. `ke`. |

### Query parameters

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `lang` | `string` | `en` | Locale code. |

### Headers

| Header | Value | Required |
| --- | --- | --- |
| `Content-Type` | `application/json` | Yes |
| `api-key` | User's auth token | Yes |

### Request body

```json
{
  "bet_id": 9081726
}
```

| Field | Type | Notes |
| --- | --- | --- |
| `bet_id` | `number` | The `id` of the bet from [Bet History](/api-reference/betting/bet-history). |

### Sample request

```bash
curl -X POST "https://api.touchvasgaming.com/1001/ke/cashout/request?lang=en" \
  -H "Content-Type: application/json" \
  -H "api-key: <user-auth-token>" \
  -d '{ "bet_id": 9081726 }'
```

### Sample response — cashout available

```json
{
  "amount": 95.5,
  "description": "Cashout available",
  "status": 1
}
```

### Sample response — cashout not available

```json
{
  "amount": 0,
  "description": "Cashout is not available at the moment",
  "status": 0
}
```

### Response field reference

| Field | Type | Notes |
| --- | --- | --- |
| `amount` | `number` | Quoted cashout value. `0` is treated by the frontend as "not available", regardless of `status`. |
| `status` | `number` | `0` = not available, non-zero = available. |
| `description` | `string` | Shown to the user; also used as the error message when `status`/`amount` indicate unavailability, or when the HTTP response is non-2xx. |

### Tenant-scoping notes for backend

- Cashout eligibility/pricing rules (margins, minimum stake, blocked markets) are tenant-specific.
- Must validate that `bet_id` belongs to a bet placed under the requesting tenant.
