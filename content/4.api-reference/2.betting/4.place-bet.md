## `POST /{tenantId}/{country}/bet`

Places a bet. This single endpoint handles four flows depending on the request body: **multibet** (all picks combined into one slip), **single bets** (one request per pick, looped client-side), **bonus-funded bets**, and **freebets**.

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. |
| `country` | `string` | Yes | Country code, e.g. `ke`. |

### Query parameters

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `lang` | `string` | `en` | Locale code. |

### Headers

| Header | Value | Required |
| --- | --- | --- |
| `Content-Type` | `application/json` | Yes |
| `api-key` | User's auth token | Yes — the frontend refuses to call this endpoint without a token. |

### Request body

```json
{
  "bet_type": 1,
  "bets": [
    {
      "market_id": 1,
      "match_id": 60417210,
      "outcome_id": "1",
      "producer_id": 1,
      "specifier": ""
    },
    {
      "market_id": 1,
      "match_id": 60417300,
      "outcome_id": "3",
      "producer_id": 1,
      "specifier": ""
    }
  ],
  "booking_code": "",
  "campaign": "null",
  "ip_address": "",
  "medium": "null",
  "referrer": "https://sportsbook.example.com/boosted",
  "source": 1,
  "stake": 100,
  "stake_type": 1,
  "utm_source": "null"
}
```

| Field | Type | Notes |
| --- | --- | --- |
| `bet_type` | `number` | `1` = multibet, `2` = single bet. Sent as `1` for freebets too (freebets are always a single-pick slip). |
| `bets` | `Array<BetItem>` | One entry per selection: `market_id`, `match_id`, `outcome_id` (string), `producer_id`, `specifier` (empty string when not applicable). |
| `booking_code` | `string` | Populated when the slip originated from a loaded booking code, otherwise `""`. |
| `campaign` / `medium` / `utm_source` | `string` | Attribution values from `localStorage`, or the literal string `"null"` when absent (not JSON `null`). |
| `referrer` | `string` | `document.referrer`, or `""` server-side/when absent. |
| `source` | `number` | Channel identifier; always `1` (web) today. |
| `stake` | `number` | Total stake for a multibet, or the single pick's stake when placing single bets individually. |
| `stake_type` | `1 \| 2 \| 3` | `1` = cash, `2` = bonus (requires `bonus_id`), `3` = freebet. |
| `bonus_id` | `number` | Present only when `stake_type` is `2`. |

### Sample request

```bash
curl -X POST "https://api.touchvasgaming.com/1001/ke/bet?lang=en" \
  -H "Content-Type: application/json" \
  -H "api-key: <user-auth-token>" \
  -d '{
    "bet_type": 1,
    "bets": [{ "market_id": 1, "match_id": 60417210, "outcome_id": "1", "producer_id": 1, "specifier": "" }],
    "booking_code": "",
    "campaign": "null",
    "ip_address": "",
    "medium": "null",
    "referrer": "",
    "source": 1,
    "stake": 100,
    "stake_type": 1,
    "utm_source": "null"
  }'
```

### Sample response — success

```json
{
  "bet_id": "TBK-2026-000123456",
  "data": "Bet Placed Successfully"
}
```

`HTTP 200` = settled/accepted immediately. `HTTP 201` = bet placement accepted but still processing; the frontend shows a generic "Bet Placement in Progress" message unless `data` is a string, in which case that string is shown instead.

### Sample response — rejected

```json
{
  "error_message": "One or more selections have suspended odds."
}
```

`HTTP 406` is treated as a distinct, expected business rejection (e.g. odds changed/suspended, stake rule violated) and is surfaced to the user differently than a generic failure. Any other non-2xx status is treated as a generic error, reading `error_message` or `message` from the body.

### Response field reference

| Field | Type | Notes |
| --- | --- | --- |
| `bet_id` | `string` | Used as the "bet code" shown to the user after placement. |
| `data` | `string \| object` | If a string, shown directly as the success message; otherwise ignored by the UI. |
| `error_message` / `message` | `string` | Read (in that priority order) to display failure reasons. |

### Tenant-scoping notes for backend

- Validate stake/odds limits from [Bet Settings](/api-reference/betting/bet-settings) and WinBoost eligibility from [WinBoost Config](/api-reference/betting/winboost-config) **per tenant**, not globally.
- `bonus_id` must be validated against bonuses issued by/for the requesting tenant.
