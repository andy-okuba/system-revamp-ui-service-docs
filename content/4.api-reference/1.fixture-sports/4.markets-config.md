## `GET /{tenantId}/{country}/markets/sports/{sportId}/config`

Returns the list of market IDs enabled/configured for a given sport (referred to as `gs_market` — "Goalscorer market" configuration — in the codebase). The frontend caches this response in `localStorage` (`marketsConfig_{sportId}`) and falls back to the cache if the request fails.

Consumed by `fetchMarketsConfig` in `stores/fixtureStore.ts`.

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. |
| `country` | `string` | Yes | Country code, e.g. `ke`. |
| `sportId` | `number` | Yes | Sport identifier. |

### Headers

| Header | Value |
| --- | --- |
| `Accept` | `application/json` |

### Sample request

```bash
curl "https://api.touchvasgaming.com/1001/ke/markets/sports/1/config" \
  -H "Accept: application/json"
```

### Sample response

```json
{
  "gs_market": [1, 18, 60, 259, 292]
}
```

### Response field reference

| Field | Type | Notes |
| --- | --- | --- |
| `gs_market` | `number[]` | Market IDs enabled for the sport. Frontend defaults to `[]` if the key is missing. |

::warning
The frontend reads **only** the `gs_market` key. Any additional metadata must be additive (extra keys are safe to add, but `gs_market` must always be present as an array).
::

### Tenant-scoping notes for backend

- This list must reflect the markets the **tenant** has switched on for the given sport — used purely as a client-side filter, so an incorrect/global list will surface markets the tenant does not actually offer.
