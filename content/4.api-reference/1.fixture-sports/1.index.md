## Purpose

This section documents every **Fixture / Sports** endpoint currently consumed by the sportsbook Nuxt UI service, and defines the **multi-tenant contract** the backend team must implement going forward.

The client code for these endpoints lives in:

- [`stores/fixtureStore.ts`](https://github.com) — endpoint URLs and fetch logic
- [`composables/useFixtures.ts`](https://github.com) — public composable surface used by pages/components
- [`types/fixture/index.ts`](https://github.com) — TypeScript contracts for requests/responses

::note
This documentation exists so the backend team can implement the multi-tenant payload contract **exactly** as consumed by the frontend. Any deviation from the shapes below will break rendering in the sportsbook UI without additional frontend changes.
::

## Current (single-tenant) base URL

```
https://api.touchvasgaming.com
```

Configured via the `NUXT_PUBLIC_BASE_FIXTURE_URL` runtime environment variable on the frontend.

## Required change: tenant scoping

Every endpoint in this service **must** be updated to accept a `tenantId` as the **first path segment**, before the existing `{country}` segment. No other part of the path, query parameters, request bodies, or response shapes changes.

::warning
**Platform-wide standard:** `/{tenantId}/{country}/` is a **mandatory** prefix on **every** endpoint across **every** service in this API reference (Fixture / Sports, Betting, Casino, Wallet, etc.), even where a service did not previously have a `{country}` path segment (e.g. Betting currently passes country as a query parameter — this must be moved into the path). This prefix is non-negotiable and applies with no exceptions. The response payload for every endpoint remains exactly as documented — only the request path changes.
::

### Path pattern

```
Before:  https://api.touchvasgaming.com/{country}/...
After:   https://api.touchvasgaming.com/{tenantId}/{country}/...
```

### `tenantId` contract

| Rule | Detail |
| --- | --- |
| Position | First path segment, before `{country}` |
| Type | `number` (positive integer), e.g. `1001`, `2002` |
| Format | Must be sent as a plain numeric path segment (no leading zeros, no non-numeric characters) |
| Required | Yes, on **every** request, including public/unauthenticated ones |
| Unknown tenant | Return `404 Not Found` with body `{ "error": "tenant_not_found", "tenant_id": <value> }` |
| Inactive/suspended tenant | Return `403 Forbidden` with body `{ "error": "tenant_inactive", "tenant_id": <value> }` |
| Data scoping | All data returned (sports, fixtures, odds, markets, tournaments, categories) must be filtered/derived from the tenant's own sportsbook configuration (enabled sports, active markets, odds margins, boosted priorities, etc.) |

::warning
`tenantId` is **not** a query parameter and is **not** a header in this contract — it is a required path segment, consistent with how `{country}` is already used. This keeps caching, routing and CDN rules simple and consistent with the rest of the path-based design.
::

### Example

```diff
- GET https://api.touchvasgaming.com/ke/v2/highlights/1
+ GET https://api.touchvasgaming.com/1001/ke/v2/highlights/1
```

## Endpoint index

| # | Method | Path (multi-tenant) | Purpose |
| --- | --- | --- | --- |
| 1 | `GET` | `/{tenantId}/{country}/v2/highlights/{sportId}` | Paginated list of fixtures/highlights for a sport |
| 2 | `GET` | `/{tenantId}/{country}/v2/match/{matchId}` | Full detail (all markets) for a single match |
| 3 | `GET` | `/{tenantId}/{country}/markets/sports/{sportId}/config` | Market IDs enabled for a sport (used for Goalscorer/GS filters) |
| 4 | `GET` | `/{tenantId}/{country}/live/counter` | Count of currently live games, grouped by sport |
| 5 | `POST` | `/{tenantId}/{country}/odd/status` | Validate current status/price of bet-slip picks before placing a bet |
| 6 | `GET` | `/{tenantId}/{country}/sports` | List of sports available for the tenant |
| 7 | `GET` | `/{tenantId}/{country}/highlight/market/alias/{sportId}` | List of highlight markets (aliases) for a sport |
| 8 | `GET` | `/{tenantId}/{country}/tournaments/{sportId}` | List of tournaments/leagues for a sport |
| 9 | `GET` | `/{tenantId}/{country}/categories/{sportId}` | List of categories/countries for a sport |

Each endpoint is documented in its own page with path/query parameters, headers, sample requests and precise sample responses matching the frontend TypeScript contracts.

## Common conventions across all endpoints

- **`{country}`**: lowercase ISO-like country code already in use today, e.g. `ke`, `ng`, `ug`. Unchanged by this update.
- **`{sportId}`**: numeric sport identifier (e.g. `1` = Football). Unchanged by this update.
- **Content type**: All responses are `application/json`. All requests send `Accept: application/json`.
- **Errors**: Non-2xx responses are surfaced by the frontend as a generic failure (`HTTP error! status: {status}`) — there is currently no structured error body contract. We recommend adopting a consistent error envelope (see [Overview conventions](#recommended-error-envelope)) tenant-wide.

## Recommended error envelope

To standardize error handling across all tenant-scoped endpoints, we recommend:

```json
{
  "error": "string (machine-readable code)",
  "message": "string (human-readable description)",
  "tenant_id": 1001,
  "status": 404
}
```

This does not change existing success payloads — it only standardizes failure responses so the frontend can eventually show tenant-aware, actionable error states.
