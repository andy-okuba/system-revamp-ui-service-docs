## `GET /{tenantId}/{country}/v2/highlights/{sportId}`

Returns a paginated list of fixtures for the given sport, filterable by market, tournament, category, boosted status, live status and date. This is the main endpoint used to render the highlights carousel, sport listing pages, live tab, boosted tab, and today/upcoming tabs.

Consumed by `fetchFixtures` in `stores/fixtureStore.ts` and exposed via `fetchFixtures`, `fetchHighlights`, `fetchLiveFixtures`, `fetchBoostedFixtures`, `fetchTodayFixtures`, `fetchUpcomingFixtures` in `composables/useFixtures.ts`.

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. See [Overview](/api-reference/fixture-sports). |
| `country` | `string` | Yes | Country code, e.g. `ke`. |
| `sportId` | `number` | Yes | Sport identifier, e.g. `1` for Football. |

### Query parameters

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `page` | `number` | `1` | 1-indexed page number. |
| `per_page` | `number` | `10` | Page size. |
| `boosted` | `"0" \| "1"` | `"0"` | `"1"` returns only boosted-odds fixtures. |
| `highlight_market_id` | `number` | `0` | Filter by market id. `0` = no filter. |
| `tournament_id` | `number` | `0` | Filter by tournament/league id. `0` = no filter. |
| `category_id` | `number` | `0` | Filter by category/country id. `0` = no filter. |
| `upcoming` | `"0" \| "1"` | `"0"` | `"1"` restricts to upcoming fixtures. |
| `today` | `"0" \| "1"` | `"0"` | `"1"` restricts to fixtures starting today. |
| `match_live_status` | `"0" \| "1"` | `"0"` | `"1"` restricts to fixtures currently live. |
| `start` | `string` (date) | — | Optional ISO date filter, sent only when a specific date is selected. |
| `specifier` | `string` | — | Sent as `total=2.5` **only** when `highlight_market_id=18` (Over/Under 2.5 highlight market). |

### Headers

| Header | Value |
| --- | --- |
| `Accept` | `application/json` |

### Sample request

```bash
curl -G "https://api.touchvasgaming.com/1001/ke/v2/highlights/1" \
  --data-urlencode "page=1" \
  --data-urlencode "per_page=10" \
  --data-urlencode "boosted=0" \
  --data-urlencode "highlight_market_id=0" \
  --data-urlencode "tournament_id=0" \
  --data-urlencode "category_id=0" \
  --data-urlencode "upcoming=0" \
  --data-urlencode "today=0" \
  --data-urlencode "match_live_status=0" \
  -H "Accept: application/json"
```

### Response field reference

| Field | Type | Notes |
| --- | --- | --- |
| `total` | `number` | Total matching records across all pages. |
| `remaining_records` | `number` | Records left to fetch after the current page (used for infinite scroll). |
| `last_page` | `number` | Total number of pages. |
| `from` / `to` | `number` | Record index range represented by the current page. |
| `data` | `ApiFixture[]` | Array of fixtures. Empty array (`[]`) signals "no more data" and stops pagination client-side. |
| `data[].highlight_market.market` | `Array<{ specifier, outcomes }>` | **Only present for handicap markets** (`market_id: 259`). When present, the frontend reads `market[0].outcomes` instead of `outcomes` directly, and also expects `handicap: true` and a populated `handicap_list: string[]`. |
| `data[].highlight_market.outcomes[].active` | `0 \| 1` | `0` hides/disables the outcome in the UI without removing it. |

::warning
When `data` is missing or not an array, the frontend treats the page as empty and stops pagination — always return `"data": []` rather than `null` or omitting the key.
::

### Tenant-scoping notes for backend

- Fixtures, odds, boosted flags/priorities and margins must reflect **the requesting tenant's** configuration (feed provider, odds markup, boosted campaigns), not a shared global feed.
- `highlight_market_id`, `tournament_id`, `category_id` filters must be evaluated against data scoped to the tenant — a tournament id valid for one tenant may not exist for another.
