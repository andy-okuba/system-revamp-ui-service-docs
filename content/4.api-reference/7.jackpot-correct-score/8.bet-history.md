## `GET /{tenantId}/{country}/jackpot/{categoryId}/bet` — Jackpot service

Returns the authenticated user's bet history **scoped to a single category**.

## `GET /{tenantId}/{country}/jackpot/bet` — Correct Score service

Returns the authenticated user's bet history **globally, across all categories** — not scoped to a single jackpot/category, unlike the Jackpot variant above.

::warning
These two endpoints have different scoping semantics despite the similar path/purpose — the Jackpot version requires a `categoryId`, the Correct Score version does not accept one at all. Confirm with backend/product whether Correct Score should eventually gain a category-scoped variant for consistency, or whether Jackpot should gain a global one.
::

Consumed by `fetchBetHistory` in `stores/jackpotBettingStore.js` (Jackpot) / `stores/correctScoreBettingStore.js` (Correct Score).

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. |
| `country` | `string` | Yes | Country code, e.g. `ke`. |
| `categoryId` | `number` | Jackpot only | The category `id` to scope history to. |

### Query parameters

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `page` | `number` | `1` | 1-indexed page number. |
| `per_page` | `number` | `10` | Page size. |
| `sort` | `string` | `created\|desc` | Sort field and direction, pipe-separated. |
| `start` / `end` | `string` (ISO date) | — | Optional date range filter. |

### Headers

| Header | Value | Required |
| --- | --- | --- |
| `api-key` | User's auth token | Yes |

### Sample request — Jackpot (per-category)

```bash
curl -G "https://api.touchvasgaming.com/1001/ke/jackpot/12/bet" \
  --data-urlencode "page=1" --data-urlencode "per_page=10" \
  -H "api-key: <user-auth-token>"
```

### Sample request — Correct Score (global)

```bash
curl -G "https://api.touchvasgaming.com/1001/ke/jackpot/bet" \
  --data-urlencode "page=1" --data-urlencode "per_page=10" \
  -H "api-key: <user-auth-token>"
```

```json

  "data": [
    {
      "id": 88200,
      "jackpot_name": "Correct Score Jackpot #601",
      "country_code": "ke",
      "created": "2026-09-20T18:32:00Z",
      "stake": 50,
      "total_games": 1,
      "possible_win": 1000000,
      "status": 0,
      "won": -1,
      "bet_type": 1,
      "bets": 1,
      "picked": [
        {
          "id": 1,
          "match_id": 60417210,
          "match_name": "Arsenal vs Chelsea",
          "home_score": "0",
          "away_score": "0",
          "won": -1,
          "results": { "home_score": "0", "away_score": "0", "picked": { "home_score": "1", "away_score": "0", "won": -1 } }
        }
```

::note
Correct Score wraps the array in `{ "data": [...] }` and normalizes a `null` `picked` field per row to `[]`; Jackpot expects (and the frontend requires) a **bare top-level array**. Recommend standardizing both on the same envelope.
::

### Tenant-scoping notes for backend

- Must only ever return bets belonging to the authenticated user within the requesting tenant.
