## `GET /{tenantId}/{country}/place/bet/status`

Checks whether the authenticated user is currently allowed to place another bet on a given jackpot, before showing the bet slip — primarily used to enforce `maximum_bets_per_profile` (from [Jackpots by Category](/api-reference/jackpot-correct-score/jackpots-by-category)). Correct Score only; no Jackpot-service equivalent exists in the frontend.

Consumed by `fetchPlaceBetStatus` in `stores/correctScoreBettingStore.js`.

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. |
| `country` | `string` | Yes | Country code, e.g. `ke`. |

### Query parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `jackpot_id` | `number` | Yes | The jackpot the user is about to bet on. |

### Headers

| Header | Value | Required |
| --- | --- | --- |
| `api-key` | User's auth token | Yes |

### Sample request

```bash
curl -G "https://api.touchvasgaming.com/1001/ke/place/bet/status" \
  --data-urlencode "jackpot_id=601" \
  -H "api-key: <user-auth-token>"
```

### Sample response — allowed (`HTTP 200`)

```json
{
  "data": "You are eligible to place a bet on this jackpot.",
  "status": 200
}
```

### Sample response — blocked (`HTTP 403`)

```json
{
  "error_response": {
    "error_code": 4291,
    "error_message": "You have reached the maximum number of bets allowed for this jackpot."
  },
  "picks": [
    { "match_id": 60417210, "home_score": 1, "away_score": 0 }
  ]
}
```

### Response field reference

| Field | Type | Notes |
| --- | --- | --- |
| `data` | `string` | Present only in the `200` (allowed) response. |
| `error_response.error_code` / `error_response.error_message` | `number` / `string` | Present only in the `403` (blocked) response — note this is **nested**, unlike every other error shape in this API which is flat. |
| `picks` | `CorrectScorePlaceBetLine[]` | Echoes back the picks that would have been submitted, present only in the `403` response — purpose unclear; confirm with backend whether the frontend is expected to do anything with this. |

::warning
This is the **only** endpoint in the entire API where the error body is nested under `error_response` instead of a flat `error_message` — flagging for consistency with the [recommended error envelope](/api-reference/fixture-sports#recommended-error-envelope).
::

### Tenant-scoping notes for backend

- `maximum_bets_per_profile` enforcement must be evaluated against the user's bets **within the requesting tenant** only.
