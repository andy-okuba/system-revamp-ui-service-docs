## Purpose

This section documents every **Jackpot** and **Correct Score** endpoint currently consumed by the sportsbook Nuxt UI service, and defines the **multi-tenant contract** the backend team must implement going forward.

The client code for these endpoints lives in:

- `stores/jackpotFixtureStore.js`, `stores/jackpotBettingStore.js`, `composables/useJackpot.js` — bundled from the internal `jackpot-ui-service` package, calling the **Jackpot** host
- `stores/correctScoreStore.js`, `stores/correctScoreBettingStore.js`, `composables/useCorrectScore.js` — same package, calling the **Correct Score** host
- `pages/correct-score/edit/[betId].vue` — consumes both hosts directly to resolve and edit an existing correct-score bet

::note
This documentation exists so the backend team can implement the multi-tenant payload contract **exactly** as consumed by the frontend. Any deviation from the shapes below will break jackpot browsing, bet placement or results without additional frontend changes.
::

## Two parallel services, two hosts

**Jackpot** (highlight-market outcome picks, e.g. 1X2 per game) and **Correct Score** (exact scoreline picks) are structurally parallel products sharing a near-identical URL scheme (`/jackpot/categories`, `/jackpot/{categoryId}`, `/jackpot/{categoryId}/results`, `/jackpot/{jackpotId}/bet`) but backed by **two separate hosts**, with real payload/response differences between them — these are **not** simply the same API mounted twice.

## Important correction to the original endpoint categorization

::warning
The original brief listed only two endpoints (`GET /jackpot/bet` on the Correct Score host, `GET /bet/history` on the Jackpot host). Code review of the bundled `jackpot-ui-service` package shows both services are full-featured: categories, jackpot/fixture browsing, results, bet placement, bet updates, bet history and a pre-bet eligibility check. These are documented in full below. The `/bet/history` path from the original brief does not match anything found in the current code — the closest equivalents are `GET /jackpot/{categoryId}/bet` (Jackpot, per-category history) and `GET /jackpot/bet` (Correct Score, global history); confirm with backend whether a `/bet/history` alias exists or the brief was inaccurate.
::

## Current (single-tenant) base URLs

```
https://api.touchvasgaming.com   (Jackpot host — NUXT_PUBLIC_JACKPOT_BASE_URL)
https://api.touchvasgaming.com   (Correct Score host — NUXT_PUBLIC_CS_BASE_URL)
```

## Required change: tenant scoping

Same platform-wide rule as the rest of the API (see the [Fixture / Sports overview](/api-reference/fixture-sports) for the full contract): every endpoint on **both** hosts **must** accept `/{tenantId}/{country}/` as the **first two path segments** — mandatory, no exceptions.

```diff
- GET https://api.touchvasgaming.com/jackpot/categories?stake_type=-1&lang=en&country_code=ke
+ GET https://api.touchvasgaming.com/1001/ke/jackpot/categories?stake_type=-1&lang=en
```

## Endpoint index

| # | Service | Method | Path (multi-tenant) | Purpose |
| --- | --- | --- | --- | --- |
| 1 | Both | `GET` | `/{tenantId}/{country}/jackpot/categories` | Active jackpot categories, filtered by stake type |
| 2 | Jackpot only | `GET` | `/{tenantId}/{country}/jackpot/categories/all` | All jackpot categories (including inactive) |
| 3 | Both | `GET` | `/{tenantId}/{country}/jackpot/{categoryId}` | Jackpots + fixtures for a category |
| 4 | Both | `GET` | `/{tenantId}/{country}/jackpot/{categoryId}/results` | Settled results for a category |
| 5 | Correct Score only | `GET` | `/{tenantId}/{country}/jackpot/{jackpotId}/result` | Settled result detail for one jackpot |
| 6 | Both | `POST` | `/{tenantId}/{country}/jackpot/{jackpotId}/bet` | Place a bet — **different payloads per service, see below** |
| 7 | Correct Score only | `POST` | `/{tenantId}/{country}/jackpot/{jackpotId}/bet/{betId}` | Update an existing (unsettled) correct-score bet |
| 8 | Jackpot only | `GET` | `/{tenantId}/{country}/jackpot/{categoryId}/bet` | Bet history, scoped to one category |
| 9 | Correct Score only | `GET` | `/{tenantId}/{country}/jackpot/bet` | Bet history, **global** across all categories |
| 10 | Correct Score only | `GET` | `/{tenantId}/{country}/place/bet/status` | Pre-bet eligibility check (max bets per profile) |

Each endpoint is documented in its own page with path/query parameters, headers, sample requests and precise sample responses matching the frontend TypeScript contracts.

## Common conventions across all endpoints

- **`lang`**: locale code, e.g. `en`. Sent as a query parameter on Jackpot-service reads; **not consistently** sent on Correct Score reads (see per-endpoint notes).
- **`{country}`**: lowercase ISO-like country code. Now a **mandatory path segment**. Historically sent as an **uppercased** `country_code` query parameter (e.g. `KE`, not `ke`) on Jackpot-service reads — flagged per-endpoint since this differs from every other category in this API, which uses lowercase.
- **Authentication**: Bet placement, bet updates, bet history and the pre-bet status check require an `api-key` header. Category/jackpot/results browsing is public.
- **Content type**: All responses are `application/json`.
- **Errors**: The frontend reads `error_message` from the JSON error body (occasionally nested under `error_response.error_message` for `403` responses — see [Place Bet Status](/api-reference/jackpot-correct-score/place-bet-status)). Standardize on a flat `error_message`; see the [recommended error envelope](/api-reference/fixture-sports#recommended-error-envelope).

### Tenant-scoping notes for backend (apply to all endpoints in this category)

- Categories, jackpots, fixtures, results and bet history are all tenant-specific (different operators run different jackpot products/prize pools).
- `api-key` identifies the user; validate it against `tenantId` on every authenticated call, consistent with every other category in this API.
