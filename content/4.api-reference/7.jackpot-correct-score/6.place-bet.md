## `POST /{tenantId}/{country}/jackpot/{jackpotId}/bet`

Places a bet against a specific jackpot. **The path is identical between the two services, but the request payload is structurally different** — the backend must accept the correct shape depending on which service the jackpot belongs to.

Consumed by `placeJackpotBet` in `stores/jackpotBettingStore.js` (Jackpot) and `placeCorrectScoreBet` in `stores/correctScoreBettingStore.js` (Correct Score).

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. |
| `country` | `string` | Yes | Country code, e.g. `ke`. |
| `jackpotId` | `number` | Yes | The jackpot `id` from [Jackpots by Category](/api-reference/jackpot-correct-score/jackpots-by-category). |

### Query parameters (Jackpot service only)

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `lang` | `string` | `en` | Locale code. |

::warning
The **Correct Score** service sends `lang` and `country_code` as **request body fields** instead of query parameters (see below) — the only place in this entire API where locale/country appear in the body rather than the URL. Standardize this alongside the mandatory path migration.
::

### Headers

| Header | Value | Required |
| --- | --- | --- |
| `Content-Type` | `application/json` | Yes |
| `api-key` | User's auth token | Yes |

### Request body — Jackpot

```json
{
  "bet_type": 1,
  "bets": [
    { "match_number": 1, "match_id": 60417210, "market_id": 1, "outcome_id": "1", "specifier": "", "producer_id": 1 },
    { "match_number": 2, "match_id": 60417300, "market_id": 1, "outcome_id": "3", "specifier": "", "producer_id": 1 }
  ],
  "booking_code": "",
  "campaign": "null",
  "ip_address": "",
  "medium": "null",
  "referrer": "",
  "source": 1,
  "stake": 100,
  "stake_type": 1,
  "utm_source": "null"
}
```

Field shapes mirror the [Betting Place Bet](/api-reference/betting/place-bet) payload, with `bets[]` additionally carrying `match_number` (position within the jackpot) and `stake_type` as a **number** (`1` = cash).

### Request body — Correct Score

```json
{
  "bet_type": 1,
  "bets": [
    { "match_id": 60417210, "home_score": 2, "away_score": 1 }
  ],
  "booking_code": "",
  "campaign": "null",
  "country_code": "ke",
  "ip_address": "",
  "lang": "en",
  "medium": "null",
  "source": 1,
  "stake": 50,
  "stake_type": "cash",
  "utm_source": "null"
}
```

| Field | Type | Notes |
| --- | --- | --- |
| `bets[].home_score` / `away_score` | `number` | The predicted exact scoreline for the fixture — **not** an `outcome_id`/`market_id` pick like the Jackpot service. |
| `country_code` | `string` | Sent in the **body**, not the URL. |
| `lang` | `string` | Sent in the **body**, not the URL. |
| `stake_type` | `string` | **String**, not a number (e.g. `"cash"`) — confirm the full enum of accepted values with backend. |

### Sample response — both services

```json
{
  "bet_id": "CS-2026-000123456",
  "data": "Bet Placed Successfully",
  "status": 201
}
```

`HTTP 201` with this exact shape (`bet_id: string`, `data: string`, `status: number`) is the **only** response the frontend accepts as success for both services — anything else is treated as a failed placement, even if the HTTP status is 2xx.

### Tenant-scoping notes for backend

- Validate stake limits and bet slip picks against the tenant's own jackpot configuration.
- `country_code`/`lang` in the Correct Score body must still be cross-checked against the mandatory `{country}` path segment for consistency.
