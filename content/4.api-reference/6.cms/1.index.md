## Purpose

This section documents every **CMS** endpoint currently consumed by the sportsbook Nuxt UI service, and defines the **multi-tenant contract** the backend team must implement going forward.

The client code for these endpoints lives in:

- `stores/cmsStore.js`, `composables/useCms.js` — bundled from the internal `cms-ui-service` package (promotions, banners, legal/static content, FAQs, social handles, contacts, popups)
- `composables/usePageMeta.ts` — a separate, direct call for per-page SEO metadata
- `pages/promotions.vue` — a **third, independent** direct call to the promotions endpoint, bypassing the package's store entirely

::note
This documentation exists so the backend team can implement the multi-tenant payload contract **exactly** as consumed by the frontend. Any deviation from the shapes below will break page SEO, promotions, legal pages, FAQs or in-app popups without additional frontend changes.
::

## Important correction to the original endpoint categorization

::warning
The original brief listed only two CMS endpoints (`get/promotions` and `meta-data/page/{pageName}`). Code review of the bundled `cms-ui-service` package shows the CMS host actually serves **all static/legal content** across the app: banners, license, privacy policy, responsible gaming, terms & conditions, bonus/affiliate terms, conflict resolution policy, important info, streaks content, FAQs (general and streaks-specific), social media handles, contacts and in-app popups. These are documented in full below.
::

## Current (single-tenant) base URL

```
https://api.touchvasgaming.com
```

Configured via the `NUXT_PUBLIC_CMS_URL` runtime environment variable on the frontend (with `NUXT_PUBLIC_CMS_SEO_URL` preferred specifically for [Page Metadata](/api-reference/cms/page-metadata) when set).

## Required change: tenant scoping

Same platform-wide rule as the rest of the API (see the [Fixture / Sports overview](/api-reference/fixture-sports) for the full contract): every endpoint **must** accept `/{tenantId}/{country}/` as the **first two path segments** — mandatory, no exceptions.

```diff
- GET https://api.touchvasgaming.com/get/promotions?lang=en&country=ke
+ GET https://api.touchvasgaming.com/1001/ke/get/promotions?lang=en
```

::warning
`pages/promotions.vue` calls `get/promotions` **directly**, independently of the package's `fetchPromotions()` — both must be migrated to the mandatory path prefix. Additionally, most of these endpoints use `country` as the query parameter name (not `country_code`, as seen in other categories) — this is dropped entirely under the new standard in favor of the mandatory `{country}` path segment.
::

## Endpoint index

| # | Method | Path (multi-tenant) | Purpose |
| --- | --- | --- | --- |
| 1 | `GET` | `/{tenantId}/{country}/meta-data/page/{pageName}` | Per-page SEO metadata (title, description, meta tags, JSON-LD schema) |
| 2 | `GET` | `/{tenantId}/{country}/get/promotions` | Promotions page content |
| 3 | `GET` | `/{tenantId}/{country}/get/banners` | Homepage/carousel banners |
| 4 | `GET` | `/{tenantId}/{country}/get/{key}` | Static/legal content — see [Legal & Static Content](/api-reference/cms/legal-content) for all 9 `key` values |
| 5 | `GET` | `/{tenantId}/{country}/get/faq` and `/get/faq/streaks` | FAQ lists — see [FAQs](/api-reference/cms/faqs) |
| 6 | `GET` | `/{tenantId}/{country}/get/smhandles` | Social media handles |
| 7 | `GET` | `/{tenantId}/{country}/get/contacts` | Support contact details |
| 8 | `GET` | `/{tenantId}/{country}/get/popups` | In-app promotional popups |

Each endpoint is documented in its own page with path/query parameters, headers, sample requests and precise sample responses matching the frontend TypeScript contracts.

## Common conventions across all endpoints

- **`lang`**: locale code, e.g. `en`. Sent as a query parameter on every endpoint.
- **`{country}`**: lowercase ISO-like country code, e.g. `ke`. Now a **mandatory path segment**, immediately after `{tenantId}` — replaces the old `country` query parameter used by the `cms-ui-service` package (note: `country`, not `country_code` as elsewhere).
- **Authentication**: None — every CMS endpoint is public/unauthenticated content.
- **Content type**: All responses are `application/json`.
- **Client-side caching**: The frontend caches every endpoint in-memory per session, with tiered TTLs — 5 minutes for banners/promotions/popups, 30 minutes for legal pages, 120 minutes for social handles/FAQs. Backend `Cache-Control` headers, if added, should not be shorter than these to avoid conflicting freshness assumptions.
- **Retry behavior**: Failed requests are retried up to 3 times with exponential backoff (1s, 2s, 4s) — **except** 4xx client errors, which fail immediately without retry. A consistent, correct use of 4xx vs 5xx status codes is therefore important for good client behavior.
- **Errors**: Endpoints vary in whether they return `{ "error": "..." }` or `{ "error_message": "..." }` on failure — standardize on one; see the [recommended error envelope](/api-reference/fixture-sports#recommended-error-envelope).

### Tenant-scoping notes for backend (apply to all endpoints in this category)

- All CMS content (promotions, banners, legal text, FAQs, contacts, popups, SEO metadata) is tenant-specific white-label content — none of it should be shared across tenants by default.
