## `GET /{tenantId}/{country}/meta-data/page/{pageName}`

Returns SEO metadata for a given logical page name, used to populate `<title>`, meta description/keywords, Open Graph/Twitter tags, and JSON-LD structured data. Called once per page render.

::warning
This endpoint is called by **two independent consumers** with different response-shape expectations:

1. `composables/usePageMeta.ts` — expects either a bare `CMSPageData` object, or `{ "data": [CMSPageData, ...] }` (takes `data[0]`)
2. `stores/cmsStore.js` → `fetchPageMetadata()` — expects `{ "data": [{ schema: {...} } , ...] }` specifically, and falls back to constructing a minimal object from `title`/`target_index`/`page_info` if `schema` is absent

**Backend team: please confirm a single canonical response shape; recommend always wrapping in `{ "data": [...] }` with a populated `schema` field, since both consumers already handle that shape.**
::

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. |
| `country` | `string` | Yes | Country code, e.g. `ke`. |
| `pageName` | `string` | Yes | Logical page identifier, e.g. `index`, `casino`, `promotions`, `login`, `join`. Lowercased and trimmed client-side before being sent. |

### Query parameters

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `lang` | `string` | `en` | Locale code. Sent by `stores/cmsStore.js`; **not** sent by `composables/usePageMeta.ts`, which relies on `{country}` alone. |

### Headers

| Header | Value |
| --- | --- |
| `Accept` | `application/json` |

### Sample request

```bash
curl -G "https://api.touchvasgaming.com/1001/ke/meta-data/page/casino" \
  --data-urlencode "lang=en"
```

### Sample response

```json
{
  "data": [
    {
      "title": "Casino Games",
      "description": "Play the best casino games online. Slots, table games, live casino and more.",
      "meta_tags": [
        { "name": "keywords", "value": "casino games, online casino, slots, live casino" },
        { "property": "og:image", "value": "https://cdn.example.com/og/casino.png" }
      ],
      "schema": "{\"@context\":\"https://schema.org\",\"@type\":\"WebPage\",\"name\":\"Casino Games\"}"
    }
  ]
}
```

### Response field reference

| Field | Type | Notes |
| --- | --- | --- |
| `data[0].title` | `string` | Used as `<title>` and `og:title`/`twitter:title` if present, otherwise the frontend falls back to a hardcoded per-page default. |
| `data[0].description` | `string` | HTML is stripped client-side before use. |
| `data[0].meta_tags` | `Array<{ name?, property?, value }>` | Arbitrary additional meta tags; `canonical`, `generator` and `viewport` keys are filtered out client-side (the frontend manages those itself). |
| `data[0].schema` | `string \| object` | JSON-LD structured data, either as a JSON string or an object — the frontend parses if it's a string. |

::note
Requests use a short client-side timeout (1.5s in dev, 2s SSR, 3s client) and silently fall back to hardcoded per-page defaults on timeout/error/404 — a slow or failing CMS never blocks page render, but also means metadata issues can go unnoticed without server-side monitoring.
::

### Tenant-scoping notes for backend

- SEO metadata (titles, descriptions, schema) is tenant-specific branding content.
