## `GET /{tenantId}/{country}/get/smhandles`

Returns the tenant's social media handles/links (Facebook, X/Twitter, Instagram, etc.).

Consumed by `fetchSocialMediaHandles` in `stores/cmsStore.js`.

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. |
| `country` | `string` | Yes | Country code, e.g. `ke`. |

### Query parameters

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `lang` | `string` | `en` | Locale code. |

### Headers

| Header | Value |
| --- | --- |
| `Accept` | `application/json` |

### Sample request

```bash
curl -G "https://api.touchvasgaming.com/1001/ke/get/smhandles" \
  --data-urlencode "lang=en"
```

### Sample response — preferred shape

```json
{
  "socialMedia": [
    { "id": 1, "name": "Facebook", "link": "https://facebook.com/example", "icon": "i-simple-icons-facebook", "language": "en", "country": "ke" },
    { "id": 2, "name": "X", "link": "https://x.com/example", "icon": "i-simple-icons-x", "language": "en", "country": "ke" }
  ]
}
```

::warning
If `socialMedia` is absent, the frontend falls back to treating **every other top-level key** in the response as a handle — e.g. `{ "facebook": "https://facebook.com/example" }` becomes `{ name: "facebook", link: "https://facebook.com/example" }`. This legacy fallback is fragile (a stray unrelated key would be misinterpreted as a social handle) — standardize on always sending the `socialMedia` array shape.
::

### Response field reference

| Field | Type | Notes |
| --- | --- | --- |
| (array item) `name` | `string` | Platform name, used for lookup via `getSocialMediaHandleByName` (case-insensitive). |
| (array item) `icon` | `string` | Icon identifier/class used directly in the UI. |

`404` is treated as "no handles found" (empty state), not a hard error.

### Tenant-scoping notes for backend

- Social handles are tenant-specific branding.
