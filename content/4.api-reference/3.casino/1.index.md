## Purpose

This section documents every **Casino** endpoint currently consumed by the sportsbook Nuxt UI service, and defines the **multi-tenant contract** the backend team must implement going forward.

The client code for these endpoints lives in:

- `stores/casinoStore.js`, `composables/useCasino.js` — bundled from the internal `casino-ui-service` package (categories, games, popular games, game launch)
- `pages/casino.vue` — providers panel (calls the Casino service directly, bypassing the package's store)
- `pages/iframe.vue` — game launch iframe (calls `/launch/url` directly with a **different payload shape** than the package's store — see [Launch Game](/api-reference/casino/launch-game))
- `pages/tournaments/[id].vue`, `components/casino-tournament.vue` — tournament detail, results/leaderboard, user position, tournament listing
- `components/casino/TopWins.vue` — recent big-win ticker

::note
This documentation exists so the backend team can implement the multi-tenant payload contract **exactly** as consumed by the frontend. Any deviation from the shapes below will break the casino lobby, game launch, or tournaments without additional frontend changes.
::

## Current (single-tenant) base URL

```
https://api.touchvasgaming.com
```

Configured via the `NUXT_PUBLIC_CASINO_BASE_URL` runtime environment variable on the frontend.

## Required change: tenant scoping

Same platform-wide rule as the rest of the API (see the [Fixture / Sports overview](/api-reference/fixture-sports) for the full contract): every endpoint **must** accept `/{tenantId}/{country}/` as the **first two path segments** — mandatory, no exceptions.

```diff
- GET https://api.touchvasgaming.com/games
+ GET https://api.touchvasgaming.com/1001/ke/games
```

::warning
Casino endpoints today are **inconsistent** about how (or whether) country is sent:

- `stores/casinoStore.js` sends `?lang=...&country_code=...` on `category`, `games`, `popular`
- `components/casino-tournament.vue` sends only `?country_code=...` (no `lang`) on `tournaments`
- `pages/casino.vue`'s direct `providers` call sends **neither** `lang` nor `country_code`
- `get/tournament/{id}`, `tournament/{id}`, `position/{id}`, `games/winnings` mix having no country parameter, or `country_code` only

Under the new standard, **all** of these must move to the mandatory `/{tenantId}/{country}/` path prefix and drop the `country_code` query parameter entirely. `lang` remains a query parameter where it is already used.
::

## Endpoint index

| # | Method | Path (multi-tenant) | Purpose |
| --- | --- | --- | --- |
| 1 | `GET` | `/{tenantId}/{country}/category` | Casino game categories |
| 2 | `GET` | `/{tenantId}/{country}/games` | Paginated, filterable casino game catalogue |
| 3 | `GET` | `/{tenantId}/{country}/providers` | Casino game providers |
| 4 | `GET` | `/{tenantId}/{country}/popular` | Paginated popular games |
| 5 | `POST` | `/{tenantId}/{country}/launch/url` | Launch a real-money or demo game session |
| 6 | `GET` | `/{tenantId}/{country}/tournaments` | List of casino tournaments |
| 7 | `GET` | `/{tenantId}/{country}/get/tournament/{tournamentId}` | Single tournament detail (prizes, games, T&Cs) |
| 8 | `GET` | `/{tenantId}/{country}/tournament/{tournamentId}` | Tournament results/leaderboard |
| 9 | `GET` | `/{tenantId}/{country}/position/{tournamentId}` | Authenticated user's own tournament position |
| 10 | `GET` | `/{tenantId}/{country}/games/winnings` | Recent big wins, used for the "Top Wins" ticker |

Each endpoint is documented in its own page with path/query parameters, headers, sample requests and precise sample responses matching the frontend TypeScript contracts.

## Common conventions across all endpoints

- **`lang`**: locale code, e.g. `en`. Sent as a query parameter where the frontend currently uses it (see per-endpoint warnings below where it is missing today).
- **`{country}`**: lowercase ISO-like country code, e.g. `ke`. Now a **mandatory path segment**, immediately after `{tenantId}` — replaces the old `country_code` query parameter used inconsistently across consumers.
- **Authentication**: Only [Position](/api-reference/casino/tournament-position) and (in one of its two call patterns) [Launch Game](/api-reference/casino/launch-game) require an `api-key` header. All other endpoints are called without authentication today.
- **Content type**: All responses are `application/json`.
- **Errors**: Several endpoints (`category`, `games`, `popular`, `launch/url`) recognize an error body shaped `{ "error_code": ..., "error_message": "..." }` and surface `error_message` to the user. Standardize on this shape platform-wide; see the [recommended error envelope](/api-reference/fixture-sports#recommended-error-envelope).

### Tenant-scoping notes for backend (apply to all endpoints in this category)

- Categories, games, providers, popular games, tournaments and top wins must all reflect the requesting **tenant's** own catalogue/provider integrations — none of this data is shared across tenants.
- `api-key` identifies the user; validate that the authenticated user belongs to the given `tenantId` and reject cross-tenant requests with `403 Forbidden`.
- Game launch must only ever return a session URL for games/providers enabled for the requesting tenant.
