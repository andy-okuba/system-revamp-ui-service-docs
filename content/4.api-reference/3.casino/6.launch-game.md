## `POST /{tenantId}/{country}/launch/url`

Requests a launch URL/session for a specific casino game, either in real-money or demo mode, to be opened in the game iframe.

::warning
**This endpoint is called with two structurally different payloads by two different parts of the frontend** — the backend must decide on and communicate a single canonical contract, as these cannot both be correct long-term:

**A. `stores/casinoStore.js` → `launchGame()`** (bundled package, used by the main casino lobby)

```json
{
  "category": "slots",
  "demo": 0,
  "device": "desktop",
  "game": "sweet-bonanza",
  "game_id": "vs20fruitsw",
  "provider_id": 12,
  "return_url": "https://sportsbook.example.com/casino?category_id=1"
}
```

**B. `pages/iframe.vue` → `getLaunchUrl()`** (used by the tournament game iframe route)

```json
{
  "account_id": 2000000019,
  "demo": true,
  "device": "desktop",
  "game_id": "vs20fruitsw",
  "game_name": "Sweet Bonanza",
  "lobby_url": "https://sportsbook.example.com/casino",
  "return_url": "https://sportsbook.example.com/casino",
  "provider_id": 12
}
```

Differences: `account_id` (B only, from `NUXT_PUBLIC_CASINO_ACCOUNT_ID`), `game_name` (B) vs `game`+`category` (A, using short names), `demo` as `0|1` (A) vs `true|false` (B), `lobby_url` (B only). **Backend team: please confirm which shape is authoritative, or whether both must be accepted.**
::

### Path parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `tenantId` | `number` | Yes | Tenant/operator identifier. |
| `country` | `string` | Yes | Country code, e.g. `ke`. |

### Query parameters

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `lang` | `string` | `en` | Locale code. |

### Headers

| Header | Value | Required |
| --- | --- | --- |
| `Content-Type` | `application/json` | Yes |
| `api-key` | User's auth token | Required by consumer **B**; consumer **A** sends it only when the user is authenticated (demo launches may omit it). |

### Sample request

```bash
curl -X POST "https://api.touchvasgaming.com/1001/ke/launch/url?lang=en" \
  -H "Content-Type: application/json" \
  -H "api-key: <user-auth-token>" \
  -d '{
    "category": "slots",
    "demo": 0,
    "device": "desktop",
    "game": "sweet-bonanza",
    "game_id": "vs20fruitsw",
    "provider_id": 12,
    "return_url": "https://sportsbook.example.com/casino"
  }'
```

### Sample response

```json
{
  "game_url": "https://provider.example.com/launch/session/abc123"
}
```

### Response field reference

| Field | Type | Notes |
| --- | --- | --- |
| `game_url` | `string` | Consumer **A** also accepts a fallback `url` field if `game_url` is absent; consumer **B** only reads `game_url`. Standardize on `game_url`. |
| `error_code` / `error_message` | — | On failure, consumer **A** reads `error_message` from the body; consumer **B** reads `error.data.error_message` and specifically checks for `error_code === 401` to redirect the user to login. |

### Tenant-scoping notes for backend

- Validate that the requested `game_id`/`provider_id` is enabled for the requesting tenant before issuing a launch session.
- `account_id` (consumer B) is currently a single hardcoded value from an environment variable — this must become tenant-derived rather than a shared constant.
